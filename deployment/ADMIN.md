# 极简管理端

管理页面放在现有前端的 `/admin`，接口在现有后端的 `/api/admin`。共用网站登录，不需要新仓库、新服务器或数据库迁移。

## 启用管理员

先注册一个正常的网站账号。管理员权限由后端环境变量中的**用户 ID**决定；前端按钮、邮箱地址或请求中的 `isAdmin` 都不能授予权限。未配置时，所有账号均无法调用管理接口。

### 1. 查询自己的用户 ID

在阿里云远程终端执行：

```bash
sudo -u postgres /usr/pgsql-16/bin/psql -d campus_wall
```

进入 `psql` 后，执行下面的查询，把示例邮箱换成自己的注册邮箱：

```sql
SELECT "id", "email", "name"
FROM public."User"
WHERE "email" = 'your-email@example.com';
```

复制结果中的完整 `id`，然后退出：

```text
\q
```

这一步只查询记录，不修改数据。也可以在已登录浏览器的开发者工具 Network 中查看 `/api/auth/me` 响应的 `data.id`。

### 2. 配置后端环境变量

已完成自动部署初始化的服务器使用以下共享配置文件：

```bash
sudo vi /opt/campus-wall/deploy/shared/.env
```

在文件末尾新增一行（如果已有该变量，则修改原行），替换为第 1 步查询到的 ID：

```dotenv
ADMIN_USER_IDS="你的完整用户ID"
```

多个管理员用英文逗号分隔。不要覆盖文件中的其他配置。`vi` 中按 `G` 到末尾，按 `o` 新起一行并进入输入模式，输入配置后按 `Esc`，输入 `:wq` 并回车保存。

本地开发则将同样的变量写入**后端**根目录的 `.env`。不要设置成 `VITE_` 变量，也不要将 `.env` 提交到仓库。

### 3. 发布代码并重启后端

本功能需要前后端代码都发布后才能在线使用。先发布后端，再发布前端；仅修改本地文件不会更新服务器。不要为了启用管理端重新运行自动部署初始化脚本。

代码已发布后，修改环境变量需要重启后端才会生效：

```bash
sudo systemctl restart campus-wall-backend
sudo systemctl status campus-wall-backend --no-pager
```

刷新网站或重新登录，在用户菜单点击「管理端」，也可以直接访问：

```text
https://campus-wall.me/admin
```

若提示无权限，确认配置的是当前账号的用户 ID、修改的是共享 `.env`，并且已重启后端。撤销权限时从变量中删除对应 ID，再重启后端。

## 页面操作

四个列表都支持搜索、分页、刷新和重置筛选。ID 可以点击复制。用户列表的「查看房间」会按房主筛选，房间列表的「查看笔触」「查看消息」会自动限定该房间。

| 页面 | 支持的操作 |
| --- | --- |
| 用户 | 查看注册邮箱、昵称、学校、注册时间及内容数量；新增账号；修改邮箱和昵称；删除账号 |
| 房间 | 查看学校及私人房间；为已有用户创建私人房间；改名；清空画板；删除私人房间 |
| 笔触 | 按完整笔触 ID、作者 ID 或邮箱查找，可限定房间 ID；预览；修改颜色和粗细；删除 |
| 聊天消息 | 按内容、完整消息 ID、作者 ID 或邮箱搜索，可限定房间 ID；编辑内容；删除 |

按笔触 ID 删除涂鸦：进入「笔触」，搜索完整 ID，核对作者与房间，点击「预览」确认位置，再点击「删除」，输入完整笔触 ID 确认。笔触预览显示它在整张画板的位置，不模拟压感。

清空画板：进入「房间」，搜索房间名或完整 ID，核对房间后点击「清空画板」，输入完整房间 ID 确认。它只删除这个房间已保存的笔触，保留聊天和房间本身；操作期间新提交的笔触仍可能出现。

用户新增功能适合管理员手动创建账号，不经过邮箱验证码流程，不代表邮箱所有权已验证。编辑用户只修改邮箱与昵称；密码仍通过网站原有密码功能维护。笔触和聊天消息的新增继续使用网站画板及聊天室。消息编辑最多支持 1000 个字符，保留原作者、房间和发送时间；编辑或删除后，所属房间的在线页面会刷新。

## 删除范围与备份

- 删除用户会同时删除其笔触、聊天消息和房间成员关系。仍拥有房间的用户不能删除，需要先处理其房间。配置为管理员的用户也不能删除，需要先在服务器撤销其管理员权限。
- 删除私人房间会删除该房间的全部笔触、聊天消息和成员关系。学校公共房间不能删除，但可以清空画板。
- 所有删除和清空操作都要求输入完整目标 ID，后端会再次验证。操作直接作用于当前后端连接的数据库，页面没有撤销功能。
- 在线画板会同步单条笔触删除和样式修改；清空画板、删除房间或清理用户内容时，受影响房间的在线页面会整体刷新，尚未提交的画笔操作或聊天输入可能丢失。已删除账号的在线连接会断开。

批量清理前，在服务器手动备份：

```bash
sudo /usr/local/sbin/campus-wall-backup
```

确认输出 `Database backup saved` 后再操作。自动部署时的备份不会在每次管理端点击删除时自动执行。备份恢复是整库操作，需单独评估覆盖范围，不能当作单条记录的「撤销」。

管理员写操作会记录操作者 ID、操作类型、目标 ID 和时间，清空画板还记录删除数量。查看近期日志：

```bash
sudo journalctl -u campus-wall-backend --since "1 hour ago" --no-pager | grep 'admin-audit'
```

列表接口不返回密码哈希或邮件验证码。日志不记录密码；这些日志用于排查，不是不可篡改的审计存储。

## 本地验证

后端：`npm test`、`npx --no-install tsc --noEmit`。接口测试注入模拟数据库，覆盖鉴权、输入校验、删除范围和在线通知，不连接 `.env` 中的数据库。

前端：`npm run build`。浏览器交互检查使用模拟账号和数据，不对生产数据库执行增删改。
